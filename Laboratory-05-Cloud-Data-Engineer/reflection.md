Object storage is better for storing millions of photos than a traditional block storage hard drive because it is built to grow easily. A hard drive has a fixed size and a folder structure that gets slow and messy when it holds millions of files. Object storage keeps each photo as an object with its own unique key and information about it, so it can keep adding more space by adding more servers.
Docker made deploying the MinIO server much easier because I did not have to install the software or set up its requirements by hand. One command downloaded the image, started the server, opened the ports, and set the login details. If something went wrong, I could remove the container and start again in seconds, which helped a lot when the original image was missing and I had to use a different one.
A bucket is a top-level container in cloud storage that holds objects, which are files together with their details. It works a bit like a main folder, but it is accessed through the internet and has its own settings for permissions and storage rules. In this lab, my bucket was called client-photos, and I uploaded a file into it. Large companies protect their data from a server crash by never keeping it in only one place. They copy the data or split it into pieces and spread them across many drives, servers, and even different locations. If one server fails, the data can still be read from the others and the missing pieces can be rebuilt. They also keep backups and older versions in case files are deleted by mistake.
My confidence with the Linux command line is growing. At the start, a small typo or a stray space broke my command, but I learned to read the error messages and fix the problem. Using docker ps and docker logs taught me how to check what is happening.
