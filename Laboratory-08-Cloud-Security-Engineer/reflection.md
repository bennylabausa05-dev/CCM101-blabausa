A host-based firewall runs on the server itself, so it checks every connection no matter where it comes from. Even if an attacker gets past the building’s network defenses or plugs into the internal network, the server still blocks anything its own rules don’t allow. 
This is called defense in depth, because one broken layer does not expose the whole system. It also connects to managing open ports, which is critical because every open port is a service listening for connections and a possible way in for an attacker. 
When you close every port the server does not need, there are fewer services to scan, exploit, or brute-force, and fewer programs to patch and monitor. This shrinks the attack surface and makes the server much easier to keep secure. The most dangerous example is leaving a database port like 3306 for MySQL open to the public internet. 
Automated scanners can find an open 3306 port within minutes, and attackers can then guess passwords or use known MySQL vulnerabilities to break in. 
Once inside, they can steal, change, or delete the company’s data, which often includes customer records and login credentials, and that can lead to financial loss, legal trouble, and damaged trust. In a real enterprise, a database should only be reachable by the application servers that need it, through a private network and strict firewall rules.
This is the same idea as in our Compose file, where the database service has no published ports, so only the Nextcloud container can reach it, and only the web port 8080 is open to users.
